# epiphany-graph-analysis — Skill Design

## Overview

A Graph-of-Thought reimplementation of `epiphany-analysis`. Takes an original text (Node A) and an analysis of that text (Node B), executes a 14-node signal-driven graph topology with parallel spawn nodes and inline role-switched blocks, and produces a rich artifact set: an enhanced version of Node A plus comprehensive cataloging of every step (analysis, ideas, accepted ideas, engineered solutions, synthesis decisions, verification audit, signal trace, execution trace).

**Design intent (in the user's words):**
> Take all of [the prompt-graph spec] into account, but the main idea is to completely enhance and revamp it for graph-of-thought-optimized pipeline and exploiting it, to produce the best end result. Produce more artifacts useful for human reviewers — ideas cataloged, solutions for each idea cataloged, full analysis at each step cataloged, capturing as much useful data as possible and saving it as .md formatted files during the process.

**Key departures from the prompt-graph input spec:**

1. **N5 LateralIdeate → N5.5 IdeaFilter → N8 SolutionEngineer** (was N5 → N8 with embedded filter). Three nodes, three artifacts: `ideas-catalog.md`, `accepted-ideas-catalog.md`, `solution-catalog.md`.
2. **N2 split into N2a + N2b as parallel spawns** (was single spawn with internal fan-out). Cleaner topology; truly independent A and B analyses; richer per-node stage files.
3. **MINIMAL mode dropped.** Two modes only: STANDARD (default) + DEEP. Fast-path users use original `epiphany-analysis`.
4. **N8 hybrid protocol** replaces `two-drafts-pick-best`: oppositional drafts → pick best → critique-and-refine (1 or 2 iterations).
5. **6 signals** (was 3): added S1_input_complexity, S4_xref_density, S5_idea_pool_thin.
6. **V1–V8 verification battery** (was R1–R6): adds V7 (graph-trace edge integrity) and V8 (topology-driven execution).
7. **`--resume` and `--retry-failed` flags** for replay-friendly operation.
8. **8 first-class user-facing markdown artifacts** in STANDARD (10 with synthesis-decisions and signal-trace, 12 in DEEP+expansion).
9. **`synthesis-decisions.md` artifact** to record N10 merge/drop decisions (replaces `merged_into` field on solution-catalog).
10. **Per-node stage files elevated to first-class artifacts** in `stages/` directory.

### 1.2 Architecture Layers (three-layer rule)

1. **Orchestrator (`SKILL.md`)** — Main agent. Parses flags, loads `graph.json`, runs PRC1 validation, executes the ready-set scheduler (inline-to-fixpoint then parallel spawn fire), handles terminal logic, writes orchestrator-assembled artifacts (`analysis-report.md`, `signal-trace.md`, `graph-trace.json`, `session.json`), emits summary line. Never modifies `graph.json` mid-run.
2. **Graph registry (`graph.json`)** — Single source of truth for topology. When module frontmatter and `graph.json` disagree, **`graph.json` wins** (source-of-truth rule).
3. **Per-node modules (`modules/N*.md`)** — Each node has a PROTOCOL section. Inline modules executed via role-switched blocks; spawn modules dispatched via `Agent` tool.

### 1.3 Topology Summary

- **14 nodes**: N1, N2a, N2b, N3, N4, N5, N5.5, N6, N7, N8, N9, N10, N11, N12
- **26 edges**: E01–E26
- **5 spawn nodes**: N2a, N2b, N5, N7, N10. Everything else inline.
- **6 signals**: S1_input_complexity, S2_thin_B, S4_xref_density, S5_idea_pool_thin, S7_no_alternatives, S11_artifact_gap
- **3 back-edges** with single-firing caps: E09 (N2b→N6), E20 (N9→N6), E26 (N12→N10)

|---|---|---|---|

### 2.2 Key Node Behaviors

#### N1 IntakeDecompose
- Reads Node A and Node B; writes verbatim to `input-a.md` and `input-b.md` (inline Node A → records `node_a_source: 'inline'`).
- **Genius Detection** on Node B: counts canonical-or-synonym headers from the 10-section Section-Tailoring Map. ≥`--genius-threshold` → `genius-current`; ≥`--drift-threshold` and < genius-threshold → `genius-drift`; else → `generic-fallback`.
- Computes **S1_input_complexity** ∈ {low, medium, high} from Node A characteristics: line_count × structural_depth × constraint_density.
- **HG-1 enforcement**: verifies `enhanced.md` target path ≠ Node A source path (trivially satisfied for inline Node A). HALT on equality.
- Required output sections: `Input Class`, `HG-1 Verification`, `Node A Decomposition`, `Node B Genius Detection`, `Complexity Signal`, `Session Init`.

#### N2a AnalyzeA + N2b AnalyzeB (parallel spawn pair)
- **N2a (Tesla hat)**: structural decomposition, key claims, apparent gaps, strengths, weaknesses on Node A. Writes `N2a-analyze-a.md`.
- **N2b (Darwin hat)**: variation survey on Node B. Genius-section processing if `genius-current/drift`, flat findings if `generic-fallback`. Raises `S2_thin_B` if Node B is generic-fallback OR <3 canonical sections. Writes `N2b-analyze-b.md`.
- N2b required output includes `Genius Detection Corroboration` to validate N1's classification.
- Both fire in parallel via ready-set scheduler — single Agent message with two parallel tool calls.

#### N5.5 IdeaFilter
- Reads `ideas-catalog.md` from N5 and `xref_map` from N4.
- Applies pro/con/utility filter using `verification-gates.md` criteria: relevance (does it map to verifiable Node A section?), feasibility (concrete-draftable?), non-redundancy (differs from already-accepted?).
- Writes `accepted-ideas-catalog.md` with each idea's score, status (ACCEPT / ACCEPT-CONDITIONAL / REJECT), rejection rationale, and `pass: original | supplemental` field.
- **Inline supplemental brainstorm**: if `accepted_count < ⌈xref_count × 0.4⌉`, raises `S5_idea_pool_thin` and runs a brief role-switched supplemental block targeting unaddressed B-findings, then re-applies filter on combined pool. Bounded ≤1 supplemental pass.

#### N8 SolutionEngineer (hybrid protocol — see Section 5 for full detail)
For each accepted idea: pick oppositional axis → draft A and draft B independently → compare and pick winner → critique against B-finding + Node A constraint → refine → (DEEP or S1=high: critique again, refine again) → final.

#### N12 Expand (DEEP only)
- Activates only on `S11_artifact_gap` from N11 in DEEP mode (E25).
- Identifies thin-spot sections in `enhanced.md`, writes `expansion-pass.md`.
- E26 back-edge fires once: feeds expansion deltas to N10 for re-synthesis. N10 renames first-pass `enhanced.md` to `enhanced-first-pass.md` before writing expanded version.

### 2.3 Spawn-vs-Inline Justification

| Decision | Rationale |
|---|---|
| N2a, N2b spawns | High-context analysis; truly independent inputs warrant parallel dispatch |
| N5 spawn | Lateral ideation needs full 1200-line context for KB |
| N7 spawn | Adversarial verification considers all candidates against falsification checklists |
| N10 spawn | Synthesis integrates 6+ upstream outputs; needs 2000 lines |
| N8 inline (2000 lines) | Hybrid protocol benefits from continuous context across solutions; saves 1 spawn; 2000-line budget matches a spawn's allocation |
| N3, N5.5, N9, N11 inline | Cheaper operations where role-switched blocks suffice |
| N6, N12 inline | Conditional control-flow nodes; small contexts; no parallelism benefit |

| E26 | N12 → N10 | **back-edge** | expansion_digest | D | N12 completed with expansions |

**Edge-type semantics:**
- **required**: target activates only when source has written SIGNAL_STATE entry. Required edges from inactive sources are dropped from working topology.
- **optional**: never blocks activation; consumed if present.
- **forward-conditional**: gate condition evaluated at ready-set compute time; blocks if false.
- **back-edge**: requires explicit enqueue from source's post-execution check. Single-firing cap.
- **gate-open**: resolves unconditionally once source executes (required-equivalent).
- **terminal**: pipeline exit.

**Gate conditions can read any SIGNAL_STATE entry**, not just the edge's source (e.g., E08's gate reads `intake_digest.node_b_type` which originates at N1).

**E24 vs E25 are mutually exclusive**: N11 fires exactly one per pass.

### 3.2 Signal System

| Signal ID | Raised By | Condition | Type | Consumed By | Effect |
|---|---|---|---|---|---|
| **S1_input_complexity** | N1 | `line_count × structural_depth × constraint_density` → {low, medium, high} | tuning | N5 (ideation breadth), N8 (iteration count) | Adjusts node-internal parameters |
| **S2_thin_B** | N2b | Node B `generic-fallback` OR <3 canonical sections | gate | E09 → N6 | Triggers early defixation |
| **S4_xref_density** | N4 | `xref_count / max(node_a_constraint_count, 1)` → {sparse, normal, dense} | tuning | N5 (lateral_pass_count: sparse=3, normal=2, dense=1) | Adjusts ideation breadth |
| **S5_idea_pool_thin** | N5.5 | `accepted_count < ⌈xref_count × 0.4⌉` | informational | N5.5 itself | Triggers inline supplemental brainstorm; logged in trace |
| **S7_no_alternatives** | N7 | All accepted ideas survive falsification with zero counter-examples | gate | E20 → N6 (if N6 not run) | Triggers late defixation |
| **S11_artifact_gap** | N11 | V6 thin-spot detection (DEEP mode, pass=1 only) | gate | E25 → N12 | Triggers expansion |

**Signal classes:**
- **Tuning** (S1, S4): adjust internal node parameters; never gate edges. Logged in `signal-trace.md`.
- **Gate** (S2, S7, S11): drive routing via gate-condition edges.
- **Informational** (S5): neither gates an edge nor tunes a downstream node; triggers in-node behavior only.

**SIGNAL_STATE invariant (PRC2):** Append-only per `(node_id, signal_field)` key. Distinct signal_fields from same node allowed (e.g., N7 writes both `falsification_result` and `adversarial_digest`).

### 3.3 Ready-Set Scheduling Protocol

```
1. compute_ready_set(SIGNAL_STATE, executed_nodes, enqueued_back_edges)
   for each active node not yet executed:
     - all required edges from active sources have SIGNAL_STATE entries? AND
     - all forward-conditional edges' gate conditions satisfied? AND
     - if back-edge-only target, is it explicitly enqueued?
     → eligible

2. inline-to-fixpoint:
   while ready_set contains inline nodes:
     pick first eligible inline node (by ascending sort_key)
     execute role-switched block per modules/N*.md
     write output to stages/, write SIGNAL_STATE entries
     check for back-edge enqueue triggers (E09, E20, E26)
     recompute ready_set

3. spawn_fire:
   if ready_set contains spawn nodes:
     dispatch ALL eligible spawn nodes in parallel
     (single Agent() message with N tool-call blocks)
     await all returns
     write outputs to stages/, write SIGNAL_STATE entries
     check for back-edge enqueue triggers
     recompute ready_set

4. terminate when N11 reaches output (E24) or hard-halt timeout
```

**Sync rules:**
- **Early back-edge sync (S2_thin_B)**: if N2b raised S2_thin_B and N6 has not yet completed, N7 is blocked from firing — prevents missing `breakthrough_digest` via E17.
- **Late back-edge sync (S7_no_alternatives)**: when N9 enqueues N6 via E20, N6 is added to N8's pending-required set for that run — N8 waits for both N9 AND N6.

### 3.5 PRC1 Validation (pre-execution)

Before execution begins:

1. **DAG check** (excluding back-edges E09, E20, E26): topological sort visits every active node.
2. **Edge resolution**: every active edge's source/target resolves to declared active node IDs (or `input`/`output` sentinels).
3. **Signal field validity**: every active edge's signal_field matches a declared digest name, gate literal (`gate:`), or `—`.
4. **Connectivity**: active subgraph (back-edges INCLUDED) is connected with N1 as source and `output` (via E24) as sink.
5. **KB file existence**: every node's referenced KB file exists at `kb/<filename>`.
6. **graph.schema.json validation**: `graph.json` validates against schema.

HALT with explicit error on any failure.

## Section 5 — N8 Hybrid Protocol Detail

The most consequential cognitive operation in the pipeline. New HG-3.

### 5.1 Inputs

From SIGNAL_STATE: `accepted_ideas_digest` (E14), `xref_map` (E12), `breakthrough_digest` (E16, optional), `adversarial_digest` (E19, optional), `falsification_digest` (E21), `intake_digest` (for S1).

From disk: `kb/oppositional-drafting-axes.md`, `kb/verification-gates.md`, `{session_dir}/input-a.md`.

### 5.2 Iteration Count Rule

| Mode | S1_complexity | Iterations after winner-pick |
|---|---|---|
| STANDARD | low | **1** (refined_v1 = final) |
| STANDARD | medium | **1** |
| STANDARD | high | **2** (refined_v2 = final) |
| DEEP | any | **2** |

### 5.3 Oppositional Drafting Axes

Defined in `kb/oppositional-drafting-axes.md`. 7 axes; selection algorithm picks per-idea.

| Axis | Pole 1 | Pole 2 | When |
|---|---|---|---|
| **A0** (default fallback) | Minimal-change | Ambitious-restructure | No clear domain pull |
| A1 | Preserve-original-voice | Rewrite-for-clarity | Touches phrasing/style |
| A2 | Conservative-scope | Expansive-scope | Scope ambiguous |
| A3 | Strict-constraint-preservation | Constraint-relaxation | Creates constraint tension |
| A4 | Abstract-principle | Specific-recipe | Principle-vs-procedure choice |
| A5 | Risk-averse | Risk-seeking | Uncertain payoff |
| A6 | Inline-integration | Sidebar-integration | Format ambiguous |

**Selection algorithm** (most-specific first; A0 fallback):

```
function pick_axis(idea, target_section, node_a_text):
    if idea.touches_phrasing_or_style:           return A1
    elif idea.scope_is_ambiguous:                return A2
    elif idea.creates_constraint_tension:        return A3
    elif idea.is_principle_vs_procedure_choice:  return A4
    elif idea.has_uncertain_payoff:              return A5
    elif idea.target_section_format_ambiguous:   return A6
    else:                                        return A0
```

### 5.4 Step-by-Step Protocol

For each accepted idea `I_n`:

1. **Pick axis** (selection algorithm above).
2. **Draft A** along pole 1 — role-switched block adopts pole-1 stance.
3. **Draft B** along pole 2 — fresh role-switched block with **Pattern α framing**: *"Forget Draft A entirely. You are drafting fresh from the idea description and pole-2 framing only. Do not echo, contrast, or reference Draft A."*
4. **Compare** drafts using `verification-gates.md` rubric. Record `comparison_rationale` naming each draft's strengths. Pick `winner ∈ {A, B}`.
5. **Critique winner** against: original B-finding, Node A constraint, loser's strengths, counter-examples from `adversarial_digest` (if available).
6. **Refine v1** addressing critique.
7. **(Conditional iteration 2)**: if iteration count = 2:
   - 7a. `critique_2`. If "no actionable defects," mark and use refined_v1 as final.
   - 7b. `refined_v2` addressing critique_2.
8. **Final** = refined_v2 (if exists) else refined_v1.
9. **Score**: pro, con, utility ∈ {high, medium, low}, status ∈ {ACCEPT, ACCEPT-CONDITIONAL, REJECT, DROPPED}.
10. **Append** full entry to `solution-catalog.md`.

### 5.5 Wall-Clock Budget for N8

- 1 iteration: ~30–60 sec/solution
- 2 iterations: ~50–90 sec/solution
- Typical run 6–12 solutions
- N8 total: ~3–18 min (mode + complexity dependent)
- **Per-module hard halt: 15 min (special case from global 10 min)**
- If approaching 75% of budget at <100% of solutions: defer remaining accepted ideas to `dropped-by-budget.md` rather than hard-halt silently

### 5.6 Failure Modes

| Failure | Handling |
|---|---|
| No applicable axis | Use A0 fallback |
| Both drafts equivalently weak | DROPPED — `both_drafts_inadequate` |
| Critique surfaces wrong-direction | DROPPED — `wrong_direction`; record both drafts and critique |
| `refined_v2` strictly worse than `refined_v1` | Use refined_v1 as final; record decision |
| Context budget exhausted mid-protocol | Halt with PARTIAL; remaining ideas DROPPED |

## Section 6 — Hard Gates & Anti-Patterns

### 6.1 Hard Gates (HG-1 through HG-5)

Absolute constraints. Violation halts the skill.

#### HG-1 — Output ≠ Input (path divergence)
N1 verifies `enhanced.md` target path ≠ Node A source path. Trivially satisfied for inline Node A (recorded as `node_a_source: 'inline'`). HALT on equality.

#### HG-2 — Self-contained runtime
Once N1 starts, no node performs:
- Web search, web fetch, scrape, MCP query (including Dify KBs)
- `grep`, `glob`, filesystem traversal beyond allowed scope
- User-facing questions

**Allowed read scope**: `{session_dir} ∪ {skill_path} ∪ {node_a_source_path} ∪ {node_b_source_path}`. Source paths read once at N1 only.

**Design-time exemption**: KB content informed by Dify queries at skill-design-time, snapshotted into `kb/*.md`. No runtime queries.

#### HG-3 — Hybrid protocol per solution
Every entry in `solution-catalog.md` with `status ∈ {ACCEPT, ACCEPT-CONDITIONAL}` must have:
1. `oppositional_axis` named
2. `draft_A`, `draft_B` both present
3. `comparison_rationale`, `winner`, `critique_1`, `refined_v1`
4. When iterations=2: `critique_2` always required; `refined_v2` required UNLESS `critique_2.verdict = 'no_actionable_defects'`
5. `final` field set

#### HG-4 — Fresh copy only
All file writes go to `{session_dir}/`. No writes to:
- Node A or Node B source directories
- `{skill_path}/` (read-only at runtime)
- Paths containing `..` traversal

#### HG-5 — Bounded iteration

| Iteration site | Cap |
|---|---|
| N5 lateral passes | ≤3 (driven by S4) |
| N5.5 supplemental brainstorm | ≤1/run |
| N8 critique-and-refine | 1 or 2/solution per §5.2 |
| Back-edge E09 | ≤1/run |
| Back-edge E20 | ≤1/run |
| Back-edge E26 | ≤1/run |
| Forward-conditional E25 | ≤1/run |
| Pipeline | ≤2 passes (first + optional expansion) |

### 6.2 Process Rules

- **PRC1** (§3.5): pre-execution topology validation
- **PRC2** (§4.14): SIGNAL_STATE append-only per `(node_id, signal_field)` key

### 6.3 Anti-Patterns (AP-1 through AP-20)

**Source preservation:**
1. DO NOT remove, paraphrase, or summarize Node A directives — verbatim preservation
2. DO NOT remove, paraphrase, or summarize Node B findings
3. DO NOT cause regression — enhanced never has less information than original
4. DO NOT overwrite original Node A (restates HG-4)

**Runtime discipline:**
5. DO NOT introduce infinite loops (restates HG-5)
6. DO NOT let runtime ask user questions or do external research (restates HG-2)
7. DO NOT assume literal persistent database — markdown + SIGNAL_STATE dict
8. DO NOT modify graph.json mid-run

**Cognitive protocol:**
9. DO NOT generate solutions outside N8 hybrid protocol (restates HG-3)
10. DO NOT treat Alternative Hypotheses as multiple competing ideas — only best-fit
11. DO NOT pick section list at runtime by guessing — use Genius Detection + Section-Tailoring Map
12. DO NOT process Section-Tailoring Map sections out of order — Headline Insight FIRST
13. DO NOT skip critique-and-refine in N8 when iteration count is configured
14. DO NOT echo, contrast, or reference Draft A while drafting Draft B (Pattern α framing)

**Topology discipline:**
15. DO NOT exceed orchestrator-level spawn budget — STANDARD ≤6, DEEP ≤7
16. DO NOT fire any back-edge more than once per run
17. DO NOT trigger expansion (E25) on N11's second verification pass — single-firing cap
18. DO NOT overwrite `enhanced.md` without preserving first-pass copy when E26 fires
19. DO NOT run all nodes regardless of input — signal-driven routing skips when conditions don't justify
20. DO NOT run analysis sequentially when ready-set scheduling would parallelize — N2a ‖ N2b dispatched in single Agent message

### 6.4 Behavior on Violation

| Violation | Response |
|---|---|
| HG-1, HG-4 (path) | HALT before any work; exit non-zero |
| HG-2 (runtime escape) | HALT with advisory naming offending operation |
| HG-3 (incomplete trail) | V1 fails; affected solutions `DROPPED — hg3_violation`; verdict at least PARTIAL |
| HG-5 (loop cap) | HALT mid-iteration; PARTIAL artifacts |
| PRC1 failure | HALT before execution |
| PRC2 violation | HALT mid-pipeline; PARTIAL artifacts |
| AP-1, AP-2, AP-3 (paraphrase/regression) | V4 fails; verdict PARTIAL; flagged in self-audit |
| AP-15 (spawn budget) | HALT before exceeding dispatch |
| AP-16, AP-17 (back-edge cap) | HALT mid-pipeline |
| AP-18 | N10 self-corrects (preserves first-pass) — internal enforcement, not external violation |

## Section 7 — Verification Battery (V1–V8)

### 7.1 Composition

V1–V6 inherit from epiphany-analysis's R1–R6 (renamed and refined). V7–V8 are GoT-specific.

| ID | Name | Class |
|---|---|---|
| V1 | Hybrid trail completeness | soft |
| V2 | Solution target verifiability | soft |
| V3 | Cross-solution non-contradiction | soft |
| V4 | Node A constraint preservation | soft |
| V5 | Output well-formedness | **hard** |
| V6 | Artifact completeness + thin-spot detection | soft (completeness) + signal-raising (thin-spot) |
| V7 | Graph-trace edge integrity | **hard** |
| V8 | Topology-driven execution | **hard** |

**Hard checks** elevate verdict directly to FAIL on any failure. **Soft checks** yield PARTIAL on partial failure.

### 7.2 Per-Check Specifications

#### V1 — Hybrid trail completeness
Every accepted/conditional solution has all HG-3 fields per §6.1. >50% failures → verdict FAIL.

#### V2 — Solution target verifiability
`target_section_in_a` references a section that exists in `input-a.md` (regex on markdown headers + `§N.M` references). Custom HTML anchors → V2 advisory (not FAIL). Hallucinated targets → solution `DROPPED — v2_hallucinated_target`.

#### V3 — Cross-solution non-contradiction
N10 pre-write contradiction check resolves first (merge-or-drop, logged in `synthesis-decisions.md`). N11 V3 re-checks; surface contradictions remaining → PARTIAL with logged pair for human review.

#### V4 — Node A constraint preservation
Every imperative/constraint in `input-a.md` (MUST/SHALL/REQUIRED/FORBIDDEN keywords + enumerated bullets) appears verbatim or fuzzy-matched (Levenshtein <10%) in `enhanced.md`. Missing constraints listed in self-audit. DEEP can trigger re-synthesis via S11.

#### V5 — Output well-formedness
N10 self-validates pre-write (1 retry). V5 catches anything missed. FAIL → verdict FAIL with PARTIAL artifacts and user-actionable error.

#### V6 — Artifact completeness + thin-spot detection
**Completeness**: all mandatory artifacts present with current timestamps:
- `enhanced.md`, `analysis-report.md`, `ideas-catalog.md`, `accepted-ideas-catalog.md`, `solution-catalog.md`, `synthesis-decisions.md`, `self-audit.md`, `signal-trace.md`, `graph-trace.json`
- DEEP-conditional: `expansion-pass.md` if N12 ran; `enhanced-first-pass.md` if E26 fired
- All executed nodes' `stages/N*.md` files

**Thin-spot detection (DEEP, pass=1 only)**: if `solution_count / xref_count < 0.6`, raises S11_artifact_gap → E25 → N12.

#### V7 — Graph-trace edge integrity
`forward_edges_fired ∪ back_edges_fired ⊆ graph.json.declared_edges`. Phantom edges → FAIL.

#### V8 — Topology-driven execution
Every executed node's activation traces to: required edge + signal satisfied, or forward-conditional + gate true, or explicit back-edge enqueue. No orchestrator improvisation. Mismatch → FAIL.

### 7.3 Verdict Aggregation

```
fails = count(checks with status=FAIL)
partials = count(checks with status=PARTIAL)

if any of {V5, V7, V8} fail: verdict = FAIL
elif fails == 0 and partials == 0: verdict = PASS
elif fails == 0: verdict = PARTIAL
else: verdict = FAIL
```

### 7.4 Verification Pass Counting

- **First pass** MAY raise S11_artifact_gap (DEEP only) → triggers expansion loop.
- **Second pass** MUST NOT raise S11 (single-firing cap on E25 prevents re-trigger).
- Second pass exits via E24 regardless of remaining thin spots; logged as PARTIAL with note `expansion_did_not_resolve_thin_spots` if applicable.

## Section 8 — Mode Behavior, Edge Cases, Errors

### 8.1 Mode Behavior

#### STANDARD (default, no flag)

Active topology: 13 nodes (all except N12). Active edges: E01–E24 (E25/E26 inactive). Wall-clock soft target ≤22 min; hard halt 35 min. Spawn count 5; budget ≤6.

Per-input-type:
- **genius-current**: full pipeline; N3 active; N6 typically not fired
- **genius-drift**: same; N3 processes matched canonical sections; unmatched flow as flat
- **generic-fallback**: N3 skipped (E08 false); N2b raises S2_thin_B → N6 runs early
- **missing**: N1 generates inline structural analysis; advisory emitted; treated as `inline-substitute`

#### DEEP (`--deep`)

Active topology: 14 nodes. Active edges: E01–E26. Wall-clock soft target ≤38 min; hard halt 55 min. N8 always 2 iterations regardless of S1.

**Expansion path**: N10 first synth → N11 → if S11 raised, E25 → N12 → E26 → N10 renames first-pass → N10 re-synth → N11 second pass (no S11 possible) → E24 → output.

#### Mode rejection

- `--minimal`: HALT — `"--minimal mode is no longer supported. Use /epiphany-analysis for fast-path runs, or run without flag for STANDARD mode."`
- Two of `{--standard, --deep}`: HALT — "Conflicting scale flags."
- Unknown flag: HALT — "Unknown flag: <flag>."
- `--resume` without `<session_dir>` arg: HALT.
- `--resume` with scale mismatch vs saved session: HALT.
- Effective `genius_threshold ≤ drift_threshold` (after defaults applied): HALT.

### 8.2 Edge Cases

| Case | Behavior |
|---|---|
| (a) Node B missing | N1 generates inline structural analysis; advisory; node_b_type='inline-substitute' |
| (b) Node B empty file | Same as (a) |
| (c) Node B not an analysis | N1 classifies generic-fallback; E08 false → N3 skipped; S2_thin_B → E09 → N6 |
| (d) Node A and Node B same file | HG-1 HALT in N1 |
| (e) All ideas rejected by N5.5 | S5 fires; supplemental fires; if still none, advisory. N8 writes empty solution-catalog. N10 produces unchanged enhanced.md + "No solutions accepted" note |
| (f) Spawn budget exhausted | Pre-check before each dispatch HALTs with `spawn_budget_exhausted` |
| (g) S2 and S7 both raised | E09 fires first; E20 sees N6 ∈ executed_nodes → does not fire |
| (h) Two solutions contradict on same section | N10 pre-write check resolves (merge or drop-lower-utility); logged in synthesis-decisions.md |
| (i) DEEP expansion no improvement | V6 second-pass detects; verdict PARTIAL with note `expansion_did_not_resolve_thin_spots` |
| (j) Node A very large (>5000 lines) | N1 advisory; S1=high; N2a/N8 may produce structural-only/dropped solutions; verdict PARTIAL with complexity note |
| (k) Node A binary or non-text | N1 HALT with "Node A must be text content" |
| (l) Inline Node A | HG-1 trivially OK; `node_a_source: 'inline'` |
| (m) Node B is itself a prior enhanced output | Treated normally; no recursion concern |
| (n) Spawn returns malformed output | Post-spawn parser fails; treated as spawn failure (§8.3); `error_msg='malformed_output: <details>'` |

### 8.3 Spawn Failure Handling

1. Log warning with node ID, error type, message, timestamp.
2. Do NOT write SIGNAL_STATE for failed node.
3. Do NOT add to `executed_nodes`.
4. Add to `session.json.failed_spawns`: `{node_id, error_msg, timestamp, retry_eligible}`. Default `retry_eligible=true`; flips to `false` after 2 retries fail.
5. Cascade-block dependents (any node with required edge from failed node).
6. Continue ready-set evaluation for unaffected nodes.
7. If cascade empties ready-set before N10 completes: HALT with `halt_reason: spawn_cascade`; PARTIAL artifacts.

### 8.3.1 Inline Node Failures

If an inline node fails (context overflow, malformed output, role-switched-block parse failure):
- HALT with `halt_reason: inline_node_failure`.
- Write current artifacts with PARTIAL status.
- Failed node's stage file written with `status: incomplete`.
- User can investigate, fix root cause, `--resume` from failed node.

### 8.4 Hard Halt Strategy

| Trigger | Action |
|---|---|
| Per-module hard halt (10 min, 15 min for N8) | Halt that node; cascade based on whether output is required |
| Mode wall-clock hard halt (35 STANDARD / 55 DEEP) | Halt entire pipeline; PARTIAL artifacts; `halt_reason: wall_clock_hard` |
| User interrupt (SIGINT) | Halt gracefully on next ready-set boundary; PARTIAL; `halt_reason: user_interrupt` |
| Spawn cascade exhaustion | Per §8.3 |
| PRC1 failure | HALT before execution; no artifacts |
| HG-1 violation | HALT in N1; minimal artifacts |

### 8.5 `--retry-failed <session_dir>`

1. Load `session.json`; validate skill_version match.
2. For each `failed_spawns` entry with `retry_eligible: true`: re-dispatch; on success update state; on failure increment counter, flip eligibility after 2 retries.
3. Resume ready-set scheduling; cascade-blocked nodes may become eligible.
4. Continue to N11 → output.
5. Empty `failed_spawns`: advisory "Session is complete; no failed spawns to retry."

### 8.6 `--resume <session_dir>`

1. Load `session.json`; validate skill_version, scale match.
2. Resume ready-set scheduling from `executed_nodes` state. Already-executed nodes NOT re-run.
3. Continue normal pipeline.

**Mixed state handling**: If `failed_spawns` non-empty, advisory: *"Session has N failed spawn(s). Use --retry-failed to retry them, or --resume to continue without retry (failed spawns will cascade-block dependents)."* User chooses.

### 8.7 Wall-Clock Advisory Tiers

`graph-trace.json.wall_clock_advisory`:
- `WITHIN_TARGET` — ≤ soft target
- `EXCEEDED_SOFT` — > soft, < hard halt
- `HALTED_HARD` — reached hard halt; PARTIAL artifacts

### 8.8 Determinism Note

The skill is **structurally deterministic** with respect to (Node A, Node B, scale, flags): same inputs produce the same `executed_nodes` set, same `back_edges_fired` set, same `signal_state_snapshot` keys, same V1–V8 verdict structure. Solution and synthesis text content varies between runs (LLM stochasticity); the topology and signal-routing decisions are reproducible.

### 9.2 Implementation Phases

Six phases; each has a deliverable and acceptance criterion. Effort: ~10.5 days raw + 30% buffer = ~14 working days.

#### Phase 1 — Design-Time Research (consolidation) [0.5 day]
**Deliverable:** This design doc. **Acceptance:** referenced precedents explicitly; explained every divergence.

#### Phase 2 — Graph Topology + Schema [1 day]
**Deliverable:** `graph.json`, `graph.schema.json`, `scripts/validate-graph.py`. **Acceptance:** validate-graph.py exits 0 on well-formed; non-zero with explanatory error on broken inputs.

#### Phase 3 — Module Protocols [4 days]
**Deliverable:** 14 files in `modules/N*.md`. Per-node frontmatter + PROTOCOL section. N8 includes full hybrid protocol; N1 includes HG-1 + S1 + genius detection; N10 includes pre-write contradiction + well-formedness checks + first-pass preservation; N11 includes V1–V8 + first/second-pass detection. **Acceptance:** every node's required output sections appear in PROTOCOL output spec; manual review.

#### Phase 4 — KB Assembly [1 day]
**Deliverable:** 12 KB files. 8 ported from graph-genius (domain-catalog, debono-techniques, ohlsson-defixation, falsification-checklists, verification-gates, blend-template, elegance-rubric, vocabulary-rubric); 3 from epiphany-analysis (section-tailoring-map, input-preloading-templates, analysis-methodology); 1 new (oppositional-drafting-axes). **Acceptance:** every KB reference in graph.json resolves.

#### Phase 5 — Orchestrator & Scripts [2 days]

SKILL.md implements: STEP 0 (flag parse + PRC1) → STEP 1 (session init) → STEP 2 (ready-set scheduler) → STEP 3 (artifact assembly) → STEP 4 (summary). Scheduler implements inline-to-fixpoint + parallel spawn dispatch + back-edge enqueue + cap enforcement + SIGNAL_STATE PRC2. **Acceptance:** SKILL.md complete; `test-runner.sh --unit` 100% pass.

#### Phase 6 — Test Battery & Final Validation [2 days]
**Deliverable:** complete `tests/`. Authors all fixtures, runs all suites, records `tests/results/<date>-results.md`. **Acceptance:** §9.1.4 (HG/PRC) 100% PASS, §9.1.5 (V1–V8) 100% PASS, ≥90% smoke + signal-routing PASS.
