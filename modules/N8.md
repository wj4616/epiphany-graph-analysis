## MACHINE ADVANTAGE

**Exploited:** Deterministic two-draft independence — the machine can genuinely draft two independent solutions by seeding each draft from different framing inputs, without the anchoring effect that makes human second drafts converge on the first.
**Instruction:** For Draft 1, frame from the B-finding perspective. For Draft 2, frame from the A-gap perspective. Do not read Draft 1 before writing Draft 2. Compare after both are written.
**Bypasses:** Human engineers anchor on their first draft when writing the second, producing near-identical alternatives. The different-framing instruction genuinely decorrelates the two drafts.

## GENIUS PERSPECTIVES

### Feynman
Mechanism: Precision in solution specification — "I know what I'm talking about when I can specify exactly what to change, not just what direction to go." Each solution must specify a concrete change to Node A, not just a direction.
Used in: Solution drafting — each draft must specify: target section, action (enhance/refine/restructure), concrete text or structural change. No vague "improve X" solutions.

### Boden
Mechanism: Classify solution type — is this a combinational change (recombining existing ideas), exploratory change (probing structure within existing constraints), or transformational change (redefining a constraint itself)? Transformational changes have higher utility but higher risk.
Used in: Solution comparison — boden_type determines how much to weight the two-draft comparison toward safety vs. novelty.

## PROTOCOL — INLINE ROLE-SWITCHED BLOCK (HG-3 enforced)

**HG-3 enforcement:** EVERY solution entry in this block must come from comparing TWO independently drafted solutions. No solution from a single draft. If both drafts fail verification, the candidate is DROPPED (no third draft).

**MINIMAL mode note:** In MINIMAL mode, ideas_digest (E11) is inactive — N5 did not run. N8 works from xref_map alone (E09). The solution pool is the xref_map entries only.

1. **Build solution candidate pool:**
   - Source 1 (always): all HIGH and MEDIUM relevance entries from xref_map
   - Source 2 (STANDARD/DEEP, if available): all ideas from ideas_digest
   - Source 3 (if available): breakthrough candidates from breakthrough_digest
   - Deduplicate: remove ideas that map to the same (A-section, action) as an existing xref entry

2. **For each solution candidate:**
   Follow the two-drafts-pick-best protocol (HG-3):

   **Draft 1 (B-finding frame):**
   Read the B-finding that seeded this candidate. Read the corresponding A-section from input-a.md.
   Draft: "Given what Node B says about [finding], the concrete change to [A-section] is: [specific text/structural change]."
   Verify: does this draft (a) reference a real A-section? (b) specify a concrete change? (c) preserve all A constraints?
   Mark as PASS or FAIL.

   **Draft 2 (A-gap frame):**
   Read the A-section gap identified by N2's A1 analysis. Do NOT read Draft 1 before writing.
   Draft: "Given the gap in [A-section], the concrete change that would close it is: [specific text/structural change]."
   Verify same criteria.
   Mark as PASS or FAIL.

   **Compare and select:**
   - Both PASS: compare on `{pro, con, utility, boden_type, information_preservation}`. Keep best. Record losing draft's cons in `comparison_rationale`.
   - One PASS, one FAIL: keep the passing draft. Note fail reason.
   - Both FAIL: DROPPED. Record to Dropped section. Do NOT retry. Advance to next candidate.

   **Assign status:**
   - ACCEPT: concrete, verifiable, preserves constraints, utility ≥ medium
   - ACCEPT-CONDITIONAL: good but depends on a condition stated explicitly
   - REJECT: utility too low, overengineers, or causes regression

3. **Write `solution-catalog.md`** to `{session_dir}/solution-catalog.md`:
   Schema per solution entry:
   ```
   ## S{NN} — <short title>
   **id:** S{NN}
   **source:** <which B-finding or A-gap>
   **target_section:** <which section of A>
   **draft_1_summary:** <first independent draft summary>
   **draft_2_summary:** <second independent draft summary>
   **comparison_rationale:** <why draft X was selected>
   **pro:** [list]
   **con:** [list]
   **utility:** high | medium | low
   **boden_type:** combinational | exploratory | transformational
   **status:** ACCEPT | ACCEPT-CONDITIONAL | REJECT
   **condition:** <only for ACCEPT-CONDITIONAL>
   **merged_into:** null | <id>
   ```
