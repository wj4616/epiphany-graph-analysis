## MACHINE ADVANTAGE

**Exploited:** Exhaustive self-audit coverage — apply all 6 R-checks without fatigue or selective reading. Humans self-audit selectively, tending to skip checks when the result looks good.
**Instruction:** Apply all 6 R-checks in order. Do not shortcut. Record PASS or FAIL for each. If any FAIL, do not stop — complete all 6 before writing the verdict.
**Bypasses:** Human self-auditors stop at the first passing check and assume the rest are fine. The machine checks all 6 regardless.

## GENIUS PERSPECTIVES

### Popper
Mechanism: The strongest evidence of correctness is a genuine failed attempt to find flaws. R1-R6 are not rubber stamps — they are active falsification attempts applied to the enhanced output.
Used in: Each R-check is framed as "try to find a violation" not "confirm correctness." R3 specifically looks for contradictions; R4 actively hunts for dropped constraints.

## PROTOCOL — SELF-AUDIT (R1-R6)

Apply all 6 checks. Record PASS or FAIL with detail for each.

**R1: Draft Comparison Check (HG-3 compliance)**
For every solution in solution-catalog.md with status ACCEPT or ACCEPT-CONDITIONAL:
- Verify that `draft_1_summary` and `draft_2_summary` are both present and non-identical
- Verify `comparison_rationale` is present and non-trivial
- PASS: all accepted solutions have ≥2 draft summaries + rationale
- FAIL: any accepted solution is missing draft comparison data

**R2: Target Section Check**
For every accepted solution in solution-catalog.md:
- Verify that `target_section` names a real section in Node A (check against input-a.md)
- PASS: all target_sections resolve to actual Node A sections
- FAIL: any target_section does not resolve (hallucinated target)

**R3: Contradiction Check**
For every pair of accepted solutions:
- Check if both target the same A-section
- If same section: verify they are compatible (composable) or that the conflict was resolved in enhanced.md
- PASS: no unresolved contradictions between solutions
- FAIL: two or more solutions targeting the same section produce contradictory changes in enhanced.md

**R4: Constraint Preservation Check**
Load the complete constraint list from N2's A1 analysis `## Constraints` section.
For each constraint:
- Verify it is still present (verbatim or semantic equivalent) in enhanced.md
- PASS: all constraints preserved
- FAIL: ≥1 constraint is absent from enhanced.md

**R5: Well-formed Markdown Check**
Read enhanced.md:
- Verify YAML frontmatter is valid (all required fields present)
- Verify no unclosed code fences, unclosed HTML tags, duplicated section headings
- Verify `## Enhancement Summary` section exists and is non-empty
- PASS: enhanced.md is well-formed with valid frontmatter
- FAIL: any structural defect found

**R6: Artifact Completeness Check**
Verify all 5 artifacts exist in `{session_dir}/` with non-zero size:
- `enhanced.md` — written by N10
- `analysis-report.md` — assembled by orchestrator (may not exist yet at N11 run time; flag as pending)
- `solution-catalog.md` — written by N8
- `self-audit.md` — written by N11 (this file, will exist after this step)
- `graph-trace.json` — assembled by orchestrator (may not exist yet; flag as pending)
In DEEP mode: if analysis-report.md or graph-trace.json are not yet written, raise `S11_artifact_gap`.
In MINIMAL/STANDARD: log advisory but do not raise signal.

**Signal evaluation — S11_artifact_gap:**
Raise `S11_artifact_gap` if: DEEP mode AND R6 finds artifacts that are pending/missing AND R1-R5 all PASS.
(If R1-R5 have failures, the primary issue is quality, not artifact completeness.)

**Overall verdict:**
- PASS: all 6 R-checks PASS
- PARTIAL: ≥1 R-check FAILS but enhanced.md exists and is coherent
- FAIL: enhanced.md does not exist or R4 (constraint preservation) FAILS
