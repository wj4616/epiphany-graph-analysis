1. Read `{session_dir}/stages/N2-dual-analyze.md` — extract B1 findings (flat or section-tailored).
2. If N3 executed (check SIGNAL_STATE for tailored_B1): read `{session_dir}/stages/N3-section-tailor.md` and use tailored findings instead of flat B1 findings.
3. Read `{session_dir}/input-a.md` (Node A) for A-section reference.
4. Read intake_digest from SIGNAL_STATE[(N1, intake_digest)] if available (optional E03).

## MACHINE ADVANTAGE

**Exploited:** Exhaustive mapping without cognitive load — cross-referencing every B-finding against every A-section systematically in a single pass, without the fatigue-driven omissions that limit human cross-referencing.
**Instruction:** For each B-finding in the input (from N3 tailored findings or N2 flat findings), scan all sections of Node A for relevance. Do not shortcut. Every B-finding gets evaluated against every A-section.
**Bypasses:** Human analysts map cross-references selectively, stopping after "enough" connections. The machine maps exhaustively.

## GENIUS PERSPECTIVES

### Tesla (bridge-builder)
Mechanism: Build bridges between systems by finding structural analogies. For each B-finding, identify the structural role it plays in A — not just topical similarity, but functional bridge potential.
Used in: Steps 2-3 — mapping B-findings to A-sections by structural role (what does this finding enable in A?), not just by keyword match.

## PROTOCOL

1. **Determine B-findings source:**
   - If `tailored_B1` is in SIGNAL_STATE (N3 executed): use N3's tailored findings (section-ordered, with source_section tags)
   - Otherwise: use N2's B1 findings (flat list)

2. **Parse Node A sections:**
   Read `input-a.md`. Extract all section headings and their associated content. Build a section index: `[{section_heading, line_range, summary}]`.

3. **Build cross-reference map:**
   For each B-finding:
   a. Identify which section(s) of Node A the finding is most relevant to
   b. Assign relevance score: HIGH (direct applicability), MEDIUM (indirect/adjacent), LOW (tangential)
   c. Identify potential action: `enhance` (add content), `refine` (improve existing content), `restructure` (reorganize), `validate` (verify claim), `remove` (flag for removal)
   d. Record: `{b_finding_id, b_finding_summary, a_section, relevance, action, rationale}`

4. **Filter:** Drop LOW relevance entries where the B-finding would not concretely improve Node A.

5. **Write `xref_map` digest to SIGNAL_STATE:**
   ```
   b_finding_count: <total B-findings processed>
   xref_entry_count: <total cross-reference mappings kept>
   xref_entries: [{b_finding_id, b_finding_summary, a_section, relevance, action, rationale}, ...]
   high_relevance_count: <N>
   signal_flags: []
   ```

6. **Write `{session_dir}/stages/N4-cross-reference.md`** with:
   - Section `## Cross-Reference Map` — full table: B-finding → A-section → relevance → action
   - Section `## B-Finding to A-Section Mappings` — detailed rationale for each mapping
   - Section `## Xref Digest` — the xref_map payload
